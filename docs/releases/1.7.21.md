# 1.7.21

## 变化

### 适配 DSH 0.2.2-rc.5

- `QUALIFIED_HOST_VERSIONS` 收进 `0.2.2-rc.5`；`package.json` 的 `dshReleases` 增补 `0.2.2-rc.4: unknown` 与 `0.2.2-rc.5: compatible`。
- 依据是**源码级比对**，不是"装上去能跑"：rc.3 与 rc.5 的 pristine npm 全树 3783 个文件逐字节相同，65 处差异里 58 处只是 `package.json` 的版本号。
- 真实代码改动只有 4 处，且都不在补丁锚点上：`dsh-base/cordis.patch.yml`（web search 改为按模型路由选后端、去掉固定 `searchProvider`）、`dsh-llm-deepseek`（新增翻译能力）、`dsh-tool-web`（搜索）、`dsh-repeat-tool-reminder`（新增 `CONTENT_REFUSED` 错误码）。
- 88 条补丁在 rc.5 pristine 源码树上 `patchDrift` 结果 `drifted = 0`。审批 / 沙箱 / 提权 / FS 围栏 / `system-prompt` / `agent-loop` / `tools` 全部逐字节相同，因此 `#9 #10 #13 #14 #15 #16` 无需重锚。

### `#35` 升级拒绝豁免长期静默失效（rc.3 起，不是 rc.5 才有）

- 宿主自 `0.2.2-rc.3` 起把升级结果的三条 `throw new Error(...)` 换成 `throw new SandboxEscalationError(..., "CODE")`，并给 `cancelled` 分支加了 `approval.signal?.throwIfAborted()`。`#35` 的两个锚点都假设旧的 `throw new Error` 形状，于是**在 rc.3 和 rc.5 上都打不上**。
- 更糟的是它当时声明了 `silentWhenMissing` + `settleWhenAbsent`，命中失败被报成 `skipped` 而不是 `drifted`：状态页看着正常，实际「用户拒绝升级仍授信」这条从来没生效。
- 现补上 rc.3/rc.5 的锚点变体，并去掉这两个软化标记，漏打会直接判 `drifted`。替换保留 `throwIfAborted()`：中断信号是「回合被打断」，不是用户拒绝，不该被一并豁免。

### `#53` 的 `web-app-lib` 判为已迁移

- `#53` 的 `file` 里 `web-app-lib` 自 0.2.1 起就不再承载「Web 身份句 + 禁止另开服务器」这段文案（rc.3 与 rc.5 该文件逐字节相同，三个锚点全不中），文案实际在 `dsh-harness-dev-context`。
- 给 `#53` 加 `fileOptional: ["web-app-lib"]`：该目标不参与漂移判定，但仍在逐文件状态里照实显示。少一条每次都报的红，避免掩盖真漂移。

### 发布源切到本仓库

- `REPOSITORY` / `SOURCE_REPO` 指向 `QCY66N/dsh-purge-`，`package.json` 的 `repository` / `homepage` / `bugs` / `install.tarball` / `install.git` 同步。
- 新增 `UPSTREAM_REPOSITORY`，并把"从 `releases/latest/download` 装过来"的识别放宽到同时接受上游与本仓库：用户从上游换过来时，`profile` 里记的还是上游 URL，认不出就会被误判成本地文件安装，从而跳过 `keepDisabled` 迁移。
- 发行包身份校验（`verifyPackageIdentity`）要求 tarball 内 `package.json` 的 `repository.url` 与本仓库严格一致，因此元数据与常量必须同时改，缺一边会报「安装包身份与发行版本不一致」。
- 身份白名单放宽为**封闭的两个仓库**（本仓库 + 上游）：回滚事务、`install-recovery`、以及以旧版本为 baseline 的升级演练都要校验上游包，只认本仓库会把「从上游换过来」这条路直接断掉。下载侧仍由 `prepareRelease` 的 URL 强等与 SHA256 兜底，白名单外的仓库照样拒绝。
- `check-bootstrap-download-runtime.mjs` 不再写死上游版本号 `1.6.38`：未显式给版本时取本仓库最新正式发行，一个都没有时明确打印 SKIP 并退出 0（新 fork 首发必然没有旧 release，否则首发自己就会 404）。

## 升级后要做的

1. 换源后先确认 `package.json` 里的 `repository.url` 与所选发行包一致，再装。
2. 打开 Purge → 状态，点一次「应用」（写入前自动备份）。
3. 自己退出并重新打开 DSH。
4. 回来看状态页：`#88` 若显示 `drifted` 而 `#87` 尚未落地，属级联预期，`patchDrift` 不计入漂移。
